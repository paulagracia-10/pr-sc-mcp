# PR-SC MCP: Context Governance for MCP-based LLM Agents

This repository contains the reproducibility materials for the study **Efficient Context Engineering for MCP-based LLM Agents: Predictive Tool Routing, Source-Aware Compression, Evidence Packaging and Observable Context Optimization**.

The study evaluates **PR-SC MCP** — Predictive Routing and Source-Aware Compression for Model Context Protocol agents — as a context-governance architecture for MCP-based LLM agents. The architecture combines predictive tool routing, source-aware compression, evidence ledgering, salience-aware evidence packaging, and an observability feedback loop.

## Repository purpose

This repository is intended to make the empirical results in the paper inspectable and reproducible. It includes:

- the final paper;
- the deterministic Architecture Validation runner;
- the Live Validation runner used with Cerebras-hosted models;
- raw and aggregated result files for the three live models;
- semantic review materials.

## Validation stages

The study has two empirical stages.

### 1. Architecture Validation

Architecture Validation is a deterministic controlled/semi-real benchmark. It evaluates eight architecture variants across 24 benchmark cases. It does not call live LLMs or live MCP servers. Its purpose is to isolate architectural mechanisms such as routing, compression, packaging, evidence retention, and robustness under controlled failure modes.

The Architecture Validation values reported in the paper are generated by:

```text
runners/architecture_validation/pr_sc_mcp_architecture_validation_runner.py
```

### 2. Live Validation

Live Validation evaluates the most diagnostic four architecture variants across three open-weight models served through Cerebras infrastructure:

- `gpt-oss-120b`
- `gemma-4-31b`
- `zai-glm-4.7`

The Live Validation matrix is:

```text
10 case families × 4 architecture variants × 5 runs × 3 models = 600 generations
```

The Live Validation runner is:

```text
runners/live_validation/v5_1_cerebras_subset_runner_v1.py
```


## Reproducing Architecture Validation

From the repository root:

```bash
python runners/architecture_validation/pr_sc_mcp_architecture_validation_runner.py --out-dir results/architecture_validation/architecture_validation_outputs
```

Expected outputs:

```text
architecture_validation_manifest.json
architecture_validation_run_records.json
architecture_validation_run_summary.csv
architecture_validation_summary_by_variant.csv
architecture_validation_case_summary.csv
```

## Reproducing Live Validation

Live Validation requires a Cerebras API key. Create a local `.env` file from the example file:

```bash
cp runners/live_validation/.env.example .env
```

Then set:

```text
CEREBRAS_API_KEY=your_key_here
```

Do not commit `.env` files or API keys.

Run the Live Validation runner according to the instructions in:

```text
runners/live_validation/README_live_validation.md
```

## Human semantic review

The `human_review/` folder contains the semantic review materials used to calibrate deterministic checks against human-reviewed answer quality. `MCP_human_review_sample_60.xlsx` is a single workbook containing the readme, scoring rubric, the 60-case review sample, the blind review template used by the reviewer, and the final aggregate-by-variant results reported in the paper (Table 9). Model and architecture-variant identity were withheld from the reviewer during scoring; see `README_human_review.md` for the full blinding protocol.
